## Summary

Implement on-device offline Optical Character Recognition (OCR) and handwriting recognition for Egyptian plumbing requisition slips. Raw extracted Arabic text lines are normalized (Eastern numerals, vulgar fractions, colloquial plumbing abbreviations), parsed into structured line items (quantities, units, query terms), and matched against the local Drift SQLite catalog with a confidence scoring engine. High-confidence items ($\ge 0.85$) are preselected, while ambiguous or low-confidence items are flagged for human review. From the interactive review screen, the merchant can make adjustments and convert the items into an official Quotation Draft or Sales Invoice with a single tap.

## Technical Context

**Language/Version**: Dart 3.13+ / Flutter 3.47+  
**Primary Dependencies**:
- `flutter_riverpod: ^3.4.3` (State management)
- `go_router: ^18.0.2` (Declarative routing)
- `drift: ^2.35.2` (Local SQLite database queries)
- `file_picker: ^13.1.0` / `image_picker` (Local image capture/gallery selection)
- `google_mlkit_text_recognition` / Native Vision / `OcrScanner` interface (100% on-device OCR)
**Storage**: Local SQLite via Drift (read-only queries against existing `products` table from Feature 002)  
**Testing**: `flutter_test` (Unit, widget, and architecture tests with `FakeOcrScanner`)  
**Target Platform**: Android (API 26+) and iOS (15.0+)  
**Project Type**: Mobile Application (Offline-First Arabic B2B ERP)  
**Performance Goals**:
- OCR text extraction & line parsing < 3.5 seconds on-device.
- Fuzzy catalog matching < 200ms for a 10-line slip against a 500-product catalog.
- Zero network round-trips.
**Constraints**:
- 100% Offline Core (Strictly zero network traffic, telemetry, or remote API calls).
- Arabic-first RTL UI with bundled Noto Sans Arabic fonts.
- Deterministic minor-unit financial calculations in downstream documents (piastres).
- Confidence threshold safety: $< 0.85$ or ambiguous top candidates must require explicit human confirmation.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Principle I: 100% Offline Operation**: PASS. OCR extraction, text normalization, regex parsing, and catalog matching execute 100% on-device in local memory and SQLite. No network connections are initiated.
- **Principle II: Cross-Platform Delivery**: PASS. Abstract `OcrScanner` interface with platform-agnostic domain logic.
- **Principle III: Local Data Ownership**: PASS. Catalog queries run against local SQLite database. Scanned image cache is managed locally and cleaned up upon session exit.
- **Principle IV: Data Integrity**: PASS. Original recognized lines and matched candidates retain provenance in the scan session state.
- **Principle V: Deterministic Financial Accuracy**: PASS. OCR never computes prices or totals. Prices are retrieved directly from SQLite catalog (`unitPricePiastres`) or entered manually by the merchant.
- **Principle VI: Evidence-Gated AI Reliability**: PASS. Clear confidence scores, match reasons, and warning indicators for ambiguous lines.
- **Principle VII: Human-in-the-Loop Control**: PASS. Items below 0.85 confidence or with competing candidates require explicit confirmation before quotation/invoice generation.
- **Principle VIII: Arabic-First Experience**: PASS. Full Arabic RTL presentation, Arabic-Indic numeral parsing, vulgar fraction handling, and Egyptian plumbing synonym mapping.
- **Principle IX: Modular Architecture**: PASS. OCR, parsing, matching, and UI are decoupled into independent layers with explicit contracts.
